# هم‌درس — برنامه‌ریز محلی مدرسه

اپ مستقل با رابط فارسی و راست‌به‌چپ برای تعریف مدرسه و ساخت برنامهٔ هفتگی. رابط در مرورگر باز می‌شود، اما پردازش و داده‌ها روی همان دستگاه هستند. استفادهٔ روزمره و PDF به اینترنت نیاز ندارند.

## مستندات کامل

- [راهنمای کاربر](docs/USER_GUIDE.md): جریان کامل برنامه‌ریزی، مثال قیود، خروجی و بازیابی.
- [معماری و تصمیم‌های طراحی](docs/ARCHITECTURE.md): اجزا، موتور حل، ممیزی و ذخیره‌سازی.
- [قالب داده و API داخلی](docs/DATA_AND_API.md): قرارداد JSON، واحد زمان، انواع قید و endpointها.
- [توسعه، آزمایش و انتشار](docs/DEVELOPMENT.md): نصب تمیز، تست مرورگر، ساخت ویندوز و رفع خطا.

مخزن: [kindtechie/school-planner](https://github.com/kindtechie/school-planner)

## اجرا

روی لینوکس:

```bash
cd school-planner
./start.sh
```

در اجرای اول، Python 3.10 یا جدیدتر، محیط venv و اینترنت برای نصب وابستگی‌ها لازم است. پس از دریافت سورس، محیط مجازی مخصوص همان دستگاه ساخته می‌شود.

روی ویندوز برای اجرای سورس، Python 3.12 نسخهٔ ۶۴بیتی نصب کنید و `start.cmd` را باز کنید. کاربر نسخهٔ نصب‌شدنی به Python یا Node.js احتیاج ندارد. برای بستن سرویس محلی، گزینهٔ «بستن برنامه» در رابط را بزنید. بستن تب مرورگر، سرویس را متوقف نمی‌کند؛ اجرای مجدد میان‌بر همان برنامه را باز می‌کند.

## ساخت نصب‌کنندهٔ ویندوز

ساخت باید روی Windows 10/11 x64 انجام شود:

1. Python 3.12 x64 و [Inno Setup 6](https://jrsoftware.org/isdl.php) را نصب کنید.
2. `build-windows.cmd` را اجرا کنید. اینترنت فقط برای دریافت وابستگی‌های مرحلهٔ ساخت لازم است.
3. نسخهٔ قابل‌حمل در `dist/HamDars` ساخته می‌شود.
4. نصب‌کننده در `dist/HamDars-Setup-1.0.0-x64.exe` ساخته می‌شود.

نصب برای کاربر جاری انجام می‌شود و دسترسی مدیر لازم ندارد. برنامه از مرورگر پیش‌فرض سیستم برای نمایش رابط استفاده می‌کند. داده‌ها بیرون از پوشهٔ نصب هستند و با ارتقا یا حذف برنامه پاک نمی‌شوند. بسته امضای تجاری ندارد. ساخت و اجرای نصب‌کنندهٔ ویندوز در محیط لینوکسی این پروژه آزمایش نشده است؛ اسکریپت ساخت و تنظیمات نصب آماده‌اند. [PyInstaller ساخت هر سیستم‌عامل را روی همان سیستم‌عامل انجام می‌دهد](https://pyinstaller.org/en/stable/usage.html#supporting-multiple-operating-systems).

برای انتقال سورس بدون محیط مجازی و داده‌های محلی، `python scripts/package-source.py` را اجرا کنید. خروجی `dist/HamDars-source-1.0.0.zip` است؛ این فایل ZIP سورس است، نه نصب‌کنندهٔ ویندوز.

## روش استفاده

1. مدرسه بسازید و روزها و تعداد زنگ‌ها را در تنظیمات وارد کنید.
2. کلاس‌ها را با نام، پایه، رشته و ساعت واقعی زنگ‌ها تعریف کنید.
3. درس‌ها و سپس دبیران، تخصص و زمان حضورشان را ثبت کنید.
4. در «جلسات و تجمیع»، تعداد جلسات هفتگی هر درس و کلاس و دبیر را مشخص کنید. چند کلاس در یک تعریف، یک جلسهٔ تجمیعی هم‌زمان می‌سازد. عنوان درس برای هر عضو کلاس تجمیعی می‌تواند متفاوت باشد.
5. محدودیت‌ها را اضافه کنید؛ هرکدام تیک فعال/غیرفعال و نوع الزام/ترجیح دارند.
6. برنامه را بسازید و گزارش ترجیح‌های رعایت‌نشده را بخوانید. سپس PDF کلاس، پایه، دبیر یا مدرسه را دریافت کنید.

برای شروع آزمایشی، فایل `examples/example-school.json` را بازیابی کنید. این نمونهٔ ساختگی شامل دو کلاس، سه دبیر، کلاس تجمیعی، قید الزامی و ترجیح است.

برای ۲٫۵ زنگ یک درس، یک تعریف با دو جلسهٔ کامل و یک تعریف با یک نیم‌زنگ وارد کنید. برای آزاد یا خودخوان، درس مربوط را تعریف کنید و دبیر انتخاب نکنید. خانهٔ خالی جدول صرفاً زمان برنامه‌ریزی‌نشده است؛ سهمیهٔ آزاد را در صورت نیاز صریحاً تعریف کنید.

با انتخاب چند دبیر برای یک درس، حل‌کننده از بین آنان انتخاب می‌کند. قید «یک دبیر برای همهٔ جلسات» مانع تغییر دبیر بین جلسات همان درس می‌شود. تخصص دبیران هنگام ذخیره کنترل می‌شود.

روی هر جلسهٔ جدول کلیک کنید تا زمان آن را ثابت یا جابه‌جا کنید. این کار یک قید قابل‌ویرایش می‌سازد؛ برای اعمال تغییر باید دوباره حل کنید. گزینهٔ «حفظ برنامهٔ قبلی» تعداد جلسات تغییرکرده را در تابع ترجیح‌ها جریمه می‌کند.

## قواعد برگرفته از مدرسه‌های فعلی

| نیاز | روش تعریف |
| --- | --- |
| حضور در روزها یا زنگ‌های مشخص | جدول حضور دبیر یا قید زمان‌های مجاز |
| زمان ثابت یک جلسه، آزمون مشترک یا استثنای زمانی | انتخاب یک جلسهٔ مشخص در قید زمان‌های مجاز |
| نبودن فاصلهٔ خالی برای دبیر یا کلاس | بدون فاصله، با واحد زنگ یا نیم‌زنگ |
| جمع‌شدن تدریس در دو روز یا حضور در همهٔ روزها | تعداد روز حضور با حداقل/حداکثر |
| سقف بار روزانه یا تعداد دقیق زنگ در یک روز | حداقل/حداکثر زنگ روزانه، با انتخاب روز |
| جلوگیری از روز تک‌زنگ | قید جلوگیری از روز تک‌زنگ |
| پخش درس در چند روز و استثنای تکرار روزانه | سقف تکرار جلسه یا تعداد روز، برای درس/کلاس موردنظر |
| دو زنگ اول یا آخر، یا سایر ترکیب‌های مجاز | الگوی روزانه؛ هر نیم‌زنگ یک صفر یا یک |
| درس‌های پشت سر هم مثل اجتماعی | جلسات پشت سر هم در یک روز |
| جلوگیری از دروس مشابه در زنگ‌های متوالی | جلسات انتخابی پشت سر هم نباشند |
| توازن بار روزانهٔ دبیر | توازن با سقف اختلاف بار روزها |
| چهارشنبه بیشتر از سه‌شنبه | مقایسهٔ دو روز با حداقل اختلاف |
| سقف دروس سنگین | انتخاب درس‌های سنگین و کلاس، سپس سقف بار روزانه |
| کامل‌کردن زنگ‌های آزاد از نیمه‌ها | قید جفت‌کردن نیم‌زنگ‌های آزاد، برای یک کلاس |
| تداخل ساعت واقعی متوسطه اول و دوم | کنترل داخلی بر اساس ساعت زنگ هر کلاس |
| ثابت‌ماندن برنامهٔ یک دبیر | قید زمان هر جلسه، یا ترجیح حفظ برنامهٔ قبلی |

دامنهٔ هر قید می‌تواند دبیر، کلاس، درس، تعریف جلسه یا یک جلسهٔ مشخص باشد. در هر گروه انتخاب‌ها با «یا» و بین گروه‌ها با «و» ترکیب می‌شوند. گروه خالی یعنی همه. انتخاب چند دبیر در یک قید، **مجموع** جلسات آن‌ها را بررسی می‌کند؛ برای شرط مستقل هر دبیر، قید جدا بسازید.

قید زمان مجاز باید تمام نیم‌زنگ‌های جلسه را پوشش دهد. برای استثنای حضور یک درس، دامنهٔ حضور عمومی دبیر را به اجتماع زمان‌های ممکن گسترش دهید و برای درس‌های دیگر قید زمان جدا تعریف کنید؛ هیچ قیدی قید الزامی دیگر را خودکار لغو نمی‌کند.

قید نرم با یک جریمه به اندازهٔ وزنش در صورت عدم رعایت کامل وارد هدف می‌شود. وزن‌ها جمع می‌شوند؛ وزن بزرگ‌تر به‌تنهایی اولویت واژگانی مطلق ایجاد نمی‌کند. حفظ برنامهٔ قبلی به ازای هر جلسهٔ جابه‌جا‌شده جریمه دارد. وضعیت «بهینه» فقط برای همین هدف تعریف‌شده است؛ «معتبر» به معنی رعایت همهٔ الزام‌هاست و لزوماً اثبات بهترین پاسخ نیست.

تداخل کلاس، تداخل ساعت واقعی دبیر و تعداد جلسات پایهٔ مسئله‌اند و همیشه الزام هستند. هم‌زمانی تجمیع بین زنگ‌بندی‌های متفاوت، بازهٔ پوشانندهٔ ساعت همهٔ اعضا را برای دبیر اشغال می‌کند.

این مخزن مستقل، انواع قواعد پروژهٔ قبلی زمان‌بندی مدارس را عمومی کرده است. داده‌ها و نسخه‌های تاریخی مدرسه‌های قبلی همراه این مخزن نیستند؛ انتقال خودکار فایل‌های قدیمی پسرانه/دخترانه/شاهد به قالب جدید در این نسخه انجام نمی‌شود. فایل قابل بازیابی، خروجی JSON همین اپ با `schemaVersion: 1` است.

## ذخیره و بازیابی

هر ثبت فرم، حذف یا تغییر تیک قید، یک تراکنش در فایل اصلی است. فرم باز تا زمان «ذخیرهٔ تغییرات» ثبت نمی‌شود. فایل پایگاه داده:

- ویندوز: `%LOCALAPPDATA%\SchoolPlanner\schools.sqlite3`
- لینوکس: `~/.local/share/SchoolPlanner/schools.sqlite3`
- مسیر سفارشی: `python run.py --data-dir /path/to/data`

خروجی JSON شامل یک مدرسه، اطلاعات و آخرین برنامه است. بازیابی فایل همیشه یک مدرسهٔ جدید می‌سازد تا نسخهٔ فعلی بازنویسی نشود. برای جابه‌جایی همهٔ داده‌ها، پس از بستن برنامه از فایل SQLite کپی بگیرید. فایل `session.url` را منتقل نکنید؛ آن فقط برای اجرای محلی جاری است.

۳۰ نسخهٔ قبلی هر مدرسه در همان پایگاه داده نگهداری می‌شود؛ بازگردانی از بخش ذخیره و بازیابی ممکن است. تاریخچه جای پشتیبان روی دستگاه دیگر را نمی‌گیرد. در ویرایش هم‌زمان دو پنجره، ذخیرهٔ نسخهٔ قدیمی رد می‌شود. اگر حین حل اطلاعات تغییر کند، نتیجهٔ قدیمی جایگزین دادهٔ جدید نمی‌شود.

پس از هر تغییر، برنامهٔ قبلی فقط برای مشاهده و راهنمای حل بعدی باقی می‌ماند و PDF آن غیرفعال می‌شود. هنگام بازیابی فایل دارای برنامهٔ قدیمی، آن برنامه کنار گذاشته می‌شود. برنامهٔ جاری واردشده دوباره ممیزی می‌شود.

## معماری

```text
run.py                  راه‌اندازی، قفل تک‌نمونه و بازکردن مرورگر
planner/domain.py       قرارداد نسخه‌دار داده و اعتبارسنجی ارجاع‌ها
planner/solver.py       تبدیل قواعد عمومی به مدل CP-SAT
planner/audit.py        کنترل مستقل برنامهٔ نهایی
planner/storage.py      تراکنش SQLite، نسخه‌بندی و تاریخچه
planner/server.py       API محلی و اجرای حل در پس‌زمینه
planner/reports.py      PDF فارسی با فونت تعبیه‌شده
web/                    رابط سادهٔ HTML/CSS/JavaScript بدون مرحلهٔ build
packaging/              بسته‌بندی اجرایی و نصب‌کنندهٔ ویندوز
tests/                  آزمایش قواعد، ذخیره و API
scripts/browser-test.cjs آزمایش واقعی رابط و دانلود خروجی‌ها
```

رابط فقط به API متصل است؛ فایل‌نویسی و قواعد در لایه‌های جدا هستند. سرور فقط روی `127.0.0.1` گوش می‌دهد، نشست محلی، کنترل Origin و کنترل هم‌زمانی نسخه دارد و سرویس اینترنتی نیست. فونت فارسی همراه برنامه است؛ مجوز آن در `web/assets/FONT-LICENSE.txt` قرار دارد.

## آزمایش

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check web/app.js
```

برای آزمایش مرورگر، Playwright در محیط ابزار توسعه و Chrome نصب باشد. سرور را با `--no-browser --data-dir /tmp/hamdars-test` اجرا کنید و `scripts/browser-test.cjs` را با مسیر `session.url` اجرا کنید. متغیر `CHROME_PATH` مسیر Chrome را تعیین می‌کند. این آزمایش مدرسه‌های آزمایشی می‌سازد؛ روی پایگاه دادهٔ کاری اجرا نکنید.

محدودیت عملی: حداکثر ۱۵۰۰ جلسه و ۲۵۰هزار گزینهٔ اولیهٔ زمان/دبیر برای هر مسئله؛ زمان حل ۱ تا ۳۰۰ ثانیه. نتیجهٔ نامشخص به‌علت پایان زمان، به‌عنوان ناممکن گزارش نمی‌شود. تشخیص تعارض یک مجموعهٔ مرتبط از قیود می‌دهد، نه لزوماً کوچک‌ترین مجموعه.
