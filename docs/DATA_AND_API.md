# قرارداد داده و API داخلی

[صفحهٔ اصلی](../README.md) · [معماری](ARCHITECTURE.md)

این مرجع مربوط به نسخهٔ فعلی کد و `schemaVersion: 1` است. منبع نهایی اعتبارسنجی [domain.py](../planner/domain.py) است. API برای رابط محلی طراحی شده و سرویس عمومی یا API دارای تضمین سازگاری مستقل نیست.

## سند مدرسه

| کلید | نوع و معنی |
| --- | --- |
| `schemaVersion` | عدد ۱؛ نسخه‌های دیگر رد می‌شوند |
| `id` | شناسهٔ مدرسه؛ رابط از UUID استفاده می‌کند |
| `name` | نام غیرخالی، حداکثر ۱۵۰ نویسه |
| `days` | آرایهٔ ۱ تا ۷ نام یکتای روز، به ترتیب جدول |
| `periods` | عدد صحیح ۱ تا ۱۰، تعداد زنگ در هر روز |
| `classes` | آرایهٔ کلاس‌ها |
| `subjects` | آرایهٔ درس‌ها |
| `teachers` | آرایهٔ دبیران |
| `lessons` | آرایهٔ تعریف جلسات تکرارشونده |
| `rules` | آرایهٔ محدودیت‌ها |
| `solution` | آخرین نتیجهٔ حل یا `null` |
| `revision` | نسخهٔ جاری ذخیره‌شده؛ هنگام ذخیره از سند دریافتی سرور استفاده شود |

تمام اعضای پنج مجموعهٔ اصلی `id` یکتا در همان مجموعه و `name` غیرخالی دارند. شناسه حداکثر ۱۰۰ و نام رکورد حداکثر ۲۰۰ نویسه است. هر مجموعه حداکثر ۱۰۰۰ رکورد دارد؛ مجموع رخدادهای گسترش‌یافته حداکثر ۱۵۰۰ است. شناسهٔ ارجاع‌شده باید موجود باشد.

نمونهٔ کامل قابل ورود: [example-school.json](../examples/example-school.json).

### کلاس

```json
{
  "id": "class-10-math",
  "name": "دهم ریاضی",
  "grade": "دهم",
  "track": "ریاضی",
  "bells": [[450, 540], [555, 645], [660, 750], [765, 855]]
}
```

هر جفت ساعت، دقیقهٔ شروع و پایان از ابتدای روز است؛ ۴۵۰ یعنی ۰۷:۳۰. تعداد جفت‌ها باید برابر `periods` باشد. بازه‌ها مرتب و بدون تداخل، طول هر بازه حداقل دو دقیقه و مرزها داخل ۰ تا ۱۴۴۰ هستند. پایه و رشته، در صورت وجود، رشتهٔ متنی حداکثر ۱۰۰ نویسه‌اند.

### درس و دبیر

درس فقط به `id` و `name` نیاز دارد. تخصص دبیر به شناسهٔ درس‌ها ارجاع می‌دهد:

```json
{
  "id": "teacher-1",
  "name": "دبیر ریاضی",
  "subjectIds": ["math"],
  "availability": [0, 1, 2, 3, 8, 9],
  "availabilityMode": "hard",
  "availabilityWeight": 10
}
```

زمان حضور، اندیس نیم‌زنگ‌های **اشغال‌شدنی** است، نه صرفاً زمان شروع. اگر `availability` حذف شود، همهٔ نیم‌زنگ‌ها مجازند؛ آرایهٔ خالی یعنی هیچ زمانی مجاز نیست. حالت پیش‌فرض `hard` و وزن پیش‌فرض ۱۰ است. وزن در بازهٔ ۱ تا ۱۰۰۰ قرار دارد.

### مختصات زمان

با `P=periods`، هر روز `H=2*P` نیم‌زنگ دارد. برای اندیس روز `d`، زنگ `p` و نیمهٔ `k`، با شماره‌گذاری صفرمبنا:

```text
start = d * H + p * 2 + k
روز = start // H
زنگ = (start % H) // 2
نیمه = start % 2
```

برای چهار زنگ: شنبهٔ زنگ اول نیمهٔ اول برابر ۰، نیمهٔ دوم برابر ۱، یکشنبهٔ زنگ اول برابر ۸ است. یک جلسهٔ کامل فقط روی اندیس زوج شروع می‌شود و دو نیمه را اشغال می‌کند. نیمهٔ دوم زنگ آخر نمی‌تواند شروع جلسهٔ کامل باشد.

### تعریف جلسه

```json
{
  "id": "lesson-math",
  "name": "ریاضی مشترک",
  "subjectId": "math",
  "classIds": ["class-10-math", "class-11-math"],
  "teacherIds": ["teacher-1"],
  "count": 3,
  "duration": 2,
  "titles": {"class-10-math": "ریاضی", "class-11-math": "حسابان"}
}
```

- `count`: تعداد صحیح ۱ تا ۱۰۰.
- `duration`: عدد ۱ برای نیم‌زنگ و ۲ برای یک زنگ.
- `classIds`: دست‌کم یک کلاس؛ چند عضو یعنی یک رویداد تجمیعی.
- `teacherIds`: گزینه‌های انتخاب دبیر؛ آرایهٔ خالی یعنی بدون دبیر.
- `subjectId`: درس مرجع که باید در تخصص تمام دبیران گزینه وجود داشته باشد.
- `titles`: عنوان نمایشی اختیاری برای اعضای همین کلاس تجمیعی؛ در انتخاب دامنهٔ درس اثری ندارد.

رخدادهای مثال بالا `lesson-math:0`، `lesson-math:1` و `lesson-math:2` هستند. شناسهٔ رخداد از شناسهٔ تعریف و شمارهٔ تکرار ساخته می‌شود؛ تغییر شناسهٔ تعریف، هویت همهٔ رخدادهایش را عوض می‌کند.

فیلد اختیاری `starts` نیز در موتور پذیرفته می‌شود و دامنهٔ سخت شروع را برای تمام تکرارهای آن تعریف محدود می‌کند. رابط عادی آن را نمی‌سازد؛ برای تنظیم زمان در رابط از قید `allowed` استفاده می‌شود. برخلاف `slots` قید، اعضای `starts` فقط شروع‌اند.

## قرارداد محدودیت

فیلدهای مشترک:

```json
{
  "id": "rule-1",
  "name": "ریاضی در سه روز",
  "kind": "day_count",
  "enabled": true,
  "mode": "hard",
  "weight": 10,
  "teacherIds": [],
  "classIds": [],
  "subjectIds": [],
  "lessonIds": ["lesson-math"],
  "eventIds": [],
  "min": 3,
  "max": 3
}
```

`mode` یکی از `hard` یا `soft` است. `enabled` در صورت حذف، true و وزن در صورت حذف، ۱۰ است. `weight` باید عدد صحیح ۱ تا ۱۰۰۰ باشد. وزن برای قید سخت اثری ندارد.

فیلترهای خالی یا حذف‌شده محدودیتی ایجاد نمی‌کنند. شرط‌های گروه‌های مختلف با AND ترکیب می‌شوند؛ اعضای هر گروه با OR. یک رویداد تجمیعی با داشتن حتی یکی از کلاس‌های انتخابی با فیلتر کلاس تطبیق دارد. فیلتر دبیر روی دبیرِ تخصیص‌یافتهٔ گزینه عمل می‌کند.

| `kind` | پارامترها و معنای دقیق |
| --- | --- |
| `allowed` | `slots`: تمام نیمه‌های اشغال هر جلسهٔ منتخب باید داخل این مجموعه باشند. آرایهٔ خالی همهٔ آن جلسات را ممنوع می‌کند. |
| `daily_load` | `min`, `max` بر حسب نیم‌زنگ؛ مجموع طول جلسات منتخب در هر روز انتخابی باید در بازه باشد. |
| `day_count` | `min`, `max` بر حسب روز؛ تعداد روزهای هفته با حداقل یک جلسهٔ منتخب. |
| `no_gaps` | `unit`: `period` یا `half`؛ واحد پیش‌فرض period. میان اشغال‌های منتخب فاصله نباشد. |
| `no_single` | بار منتخب روز نباید دقیقاً ۲ نیم‌زنگ باشد. |
| `spread` | `max`: سقف تعداد رخداد در روز، مستقل از طول جلسه. `min` در منطق این قید استفاده نمی‌شود. |
| `pattern` | `patterns`: آرایهٔ الگوها؛ طول هر الگو `2*periods` و اعضا ۰ یا ۱. بردار اشغال روز باید یکی از الگوها باشد. |
| `consecutive` | همهٔ جلسات منتخب حداکثر در یک روز، بدون فاصلهٔ نیم‌زنگی میان اشغال‌ها باشند. |
| `same_teacher` | تعداد مقادیر مختلف دبیر تخصیص‌یافتهٔ منتخب حداکثر یک باشد؛ مقدار بدون دبیر نیز یک مقدار متمایز محسوب می‌شود. |
| `balance` | `max`: سقف اختلاف بار روزانه بر حسب نیم‌زنگ، شامل روزهای خالی. |
| `day_compare` | `dayA`, `dayB`: اندیس روز؛ بار A حداقل `min` نیم‌زنگ از B بیشتر باشد. `max` در منطق مقایسه استفاده نمی‌شود. |
| `not_adjacent` | هیچ دو رخداد منتخب در دو زنگ همسایهٔ یک روز قرار نگیرند. |
| `paired_halves` | نیمه‌های اشغال منتخب جفت باشند؛ فقط اگر تعداد نیمه‌های اشغال فرد باشد، یک نیمهٔ جفت‌نشده مجاز است. برای آزادِ یک کلاس طراحی شده است. |

`days` برای `daily_load`، `no_gaps`، `no_single`، `spread`، `pattern` و `balance` روزهای اعمال را تعیین می‌کند؛ خالی یا حذف‌شده یعنی همهٔ روزها. در حالت داخلی `consecutive` نیز این فیلد بررسی فاصله را محدود می‌کند، ولی شرط تک‌روز بودن سراسری است؛ رابط برای این نوع روز انتخاب نمی‌کند. در انواع دیگر روی `days` برای محدودسازی حساب نکنید.

برای انواع دارای `min`/`max`، مقادیر صحیح نامنفی تا ۳۰۰۰ و `min <= max` اعتبارسنجی می‌شوند؛ مقدار حذف‌شده صفر است. پارامترهای مربوط را صریح وارد کنید. رابط مقادیر زنگی را پیش از ارسال در ۲ ضرب می‌کند؛ تعداد روز و تعداد جلسه تبدیل واحد ندارند.

حضور هر دبیر در زمان حل به یک قید `allowed` داخلی با شناسهٔ `availability:<teacherId>` تبدیل می‌شود. این قواعد در `rules` سند ذخیره نمی‌شوند، ولی در گزارش ممیزی حضور دارند.

## نتیجهٔ حل

نتیجه می‌تواند شامل این فیلدها باشد:

| فیلد | معنی |
| --- | --- |
| `status` | وضعیت OR-Tools: `OPTIMAL`, `FEASIBLE`, `INFEASIBLE`, `UNKNOWN` یا وضعیت خطای مدل |
| `seconds` | زمان فراخوانی حل؛ زمان کامل ساخت مدل را شامل نمی‌شود |
| `schedule` | فقط در نتیجهٔ معتبر؛ آرایهٔ `{id, start, teacherId}` |
| `audit` | اعتبار کلی، خطاها، وضعیت قواعد و جریمهٔ واقعی ترجیح‌ها |
| `objective`, `bound` | مقدار هدف مدل و کران حل‌کننده |
| `changed` | تعداد رخدادهای دارای سابقه که زمان یا دبیرشان تغییر کرده |
| `preserveWeight` | وزن جریمهٔ هر تغییر |
| `conflicts` | در ناممکنی، نام قیدهای مرتبط با تعارض |
| `message` | توضیح قابل نمایش |
| `stale` | در صورت ویرایش بعدی مدرسه، true می‌شود |

وضعیت ممیزی هر قید شامل `id`, `name`, `mode`, `satisfied`, `weight` است. `audit.penalty` فقط ترجیح‌ها را حساب می‌کند و شامل جریمهٔ حفظ برنامه نیست. در پاسخ FEASIBLE نیز وضعیت واقعی ترجیح‌ها را از ممیزی بخوانید.

هنگام ذخیرهٔ عادی، سرور `solution` ارسال‌شدهٔ مرورگر را جایگزین نتیجهٔ خودش نمی‌کند. ورود فایل یا ثبت نتیجهٔ حل مسیرهای جداگانهٔ ممیزی دارند. revision جدید را همیشه از پاسخ سرور بگیرید.

## API داخلی

نشانی پایهٔ نشست، `http://127.0.0.1:<port>` است. همهٔ مسیرهای زیر به cookie نشست نیاز دارند. درخواست‌های POST با `Content-Type: application/json` و بدنهٔ JSON object ارسال می‌شوند. API هدر CORS عمومی ندارد.

| روش و مسیر | ورودی | پاسخ |
| --- | --- | --- |
| `GET /api/state` | — | فهرست خلاصهٔ مدرسه‌ها، انواع قید و مسیر DB |
| `GET /api/school?id=…` | شناسهٔ مدرسه | سند کامل مدرسه |
| `GET /api/history?id=…` | شناسهٔ مدرسه | revision و زمان جایگزینی نسخه‌های قبلی |
| `GET /api/export?id=…` | شناسهٔ مدرسه | دانلود JSON یک مدرسه |
| `GET /api/pdf?id=…&view=…&target=…` | `view`: school/class/grade/teacher؛ target اختیاری | PDF؛ نبودن target یعنی همهٔ موارد آن نما |
| `GET /api/job?id=…` | شناسهٔ job | وضعیت running/done/error و در پایان نتیجه |
| `POST /api/create` | `{ "name": "مدرسه" }` | مدرسهٔ تازه با revision اولیهٔ ذخیره‌شده |
| `POST /api/import` | `{ "school": <document> }` | سند با شناسهٔ جدید؛ بدون بازنویسی نسخهٔ قبلی |
| `POST /api/save` | سند کامل شامل revision موردانتظار | سند ذخیره‌شده و revision جدید |
| `POST /api/delete` | `{ "id": "…", "revision": 3 }` | `{ "ok": true }`؛ همراه حذف تاریخچه |
| `POST /api/restore` | `{ "id": "…", "revision": 2 }` | بازگردانی revision تاریخی و ایجاد revision جدید |
| `POST /api/solve` | `{ "id": "…", "seconds": 30, "preserveWeight": 10 }` | `{ "jobId": "…" }` |
| `POST /api/quit` | `{}` | `{ "ok": true }` و خاموش‌شدن سرویس |

در PDF، target برای کلاس و دبیر شناسه و برای پایه متن پایه است؛ در نمای school انتخاب target کاربردی ندارد. نتیجهٔ قدیمی یا نامعتبر برای PDF پذیرفته نمی‌شود.

زمان حل در API بین ۱ و ۳۰۰ ثانیه و وزن حفظ برنامه بین ۰ و ۱۰۰۰ است. برنامه فقط آخرین job را در حافظه نگه می‌دارد. هنگام ساخت، poll با فاصلهٔ یک ثانیه مانند رابط فعلی کافی است.

خطاها معمولاً JSON با کلید `error` هستند:

- ۴۰۰: ورودی یا عملیات نامعتبر؛ از جمله مدرسه یا نسخهٔ تاریخی پیدا نشده.
- ۴۰۳: نشست، Host یا Origin نامعتبر.
- ۴۰۴: مسیر API یا فایل static ناشناخته.
- ۴۰۹: تعارض revision، شناسهٔ تکراری یا درحال‌اجرا بودن حل دیگر.
- ۵۰۰: خطای داخلی.

فایل `session.url` برای استفادهٔ محلی نگهداری می‌شود؛ مقدار واقعی آن را در نمونه‌کدها، لاگ عمومی، Git یا گزارش خطا منتشر نکنید.

## SQLite و نسخه‌بندی

`schools` ستون‌های `id`, `revision`, `document`, `updated` و `history` ستون‌های `school_id`, `revision`, `document`, `updated` دارد. سند به‌صورت JSON متنی UTF-8 و زمان به‌صورت ISO در UTC ذخیره می‌شود. زمان تاریخچه زمان جایگزین‌شدن آن سند است، نه زمان اولیهٔ ساختش.

نسخهٔ فایل با `schemaVersion` و نسخهٔ ویرایش با `revision` دو مفهوم متفاوت‌اند. تغییر اول به migration قرارداد نیاز دارد؛ دومی برای جلوگیری از ذخیرهٔ هم‌زمان ناسازگار است. به‌جای ویرایش دستی DB، از رابط، ورود JSON یا API اعتبارسنجی‌شده استفاده کنید.
