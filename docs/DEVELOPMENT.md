## دریافت و راه‌اندازی تمیز

```bash
 git clone https://github.com/kindtechie/school-planner.git
 cd school-planner
 python3 -m venv .venv
 .venv/bin/python -m pip install -r requirements.txt
 .venv/bin/python run.py
```

Python 3.10 یا جدیدتر برای اجرای سورس لازم است. مسیر ساخت ویندوز مشخصاً Python 3.12 x64 را استفاده می‌کند. روی بعضی توزیع‌های لینوکس باید بستهٔ venv سیستم نصب باشد. اینترنت فقط هنگام دریافت سورس و نصب وابستگی‌ها لازم است. وابستگی‌های مستقیم در `requirements.txt` نسخهٔ مشخص دارند؛ وابستگی‌های گذرا در این نسخه lock کامل ندارند.

فرانت مرحلهٔ build ندارد. فایل‌های `web/` مستقیماً از سرور محلی سرو می‌شوند. Node.js برای اجرای برنامه، تولید PDF یا ساخت نصب‌کننده لازم نیست؛ فقط بررسی syntax و آزمایش مرورگر توسعه از آن استفاده می‌کنند.

میان‌برهای سورس:

- لینوکس: `./start.sh`
- ویندوز: `start.cmd`

این میان‌برها در صورت نبودن محیط مجازی آن را می‌سازند و وابستگی‌ها را نصب می‌کنند. پس از تغییر requirements در محیط موجود، نصب وابستگی‌ها را دستی دوباره اجرا کنید. برای اطمینان از مفسر درست، `python -m pip` با مسیر محیط مجازی را ترجیح دهید.

## پارامترهای اجرا

```bash
.venv/bin/python run.py --data-dir /tmp/hamdars-dev --port 8765 --no-browser
```

| گزینه | کاربرد |
| --- | --- |
| `--data-dir` | پوشهٔ مستقل داده؛ مناسب آزمایش، نسخهٔ توسعه یا چند مجموعهٔ جدا |
| `--port` | پورت ثابت اختیاری؛ مقدار پیش‌فرض صفر یعنی انتخاب خودکار |
| `--no-browser` | مرورگر خودکار باز نشود |

خروجی ترمینال فقط آدرس پایه را نشان می‌دهد. برای ورود اولیه به نشست، آدرس خصوصی داخل `session.url` همان پوشهٔ داده استفاده می‌شود. بازکردن مستقیم آدرس پایه در مرورگری بدون cookie نشست، خطای ۴۰۳ می‌دهد.

تغییر فرانت با بازخوانی مرورگر دیده می‌شود؛ تغییر Python نیاز به توقف و اجرای مجدد سرویس دارد. خاموش‌کردن از گزینهٔ رابط یا Ctrl+C در اجرای ترمینالی انجام می‌شود.

## محل داده و بازیابی عملیاتی

مسیر پیش‌فرض:

| سیستم | مسیر |
| --- | --- |
| Windows | `%LOCALAPPDATA%\SchoolPlanner` |
| Linux | `~/.local/share/SchoolPlanner` |

در نبودن LOCALAPPDATA، مسیر مبتنی بر خانهٔ کاربر استفاده می‌شود. پوشهٔ داده این فایل‌ها را دارد:

- `schools.sqlite3`: همهٔ مدارس و تاریخچه‌های آن‌ها.
- `instance.lock`: فایل قفل تک‌پردازش؛ وجود فایل به‌تنهایی به معنی قفل فعال نیست.
- `session.url`: آدرس نشست جاری؛ هنگام خروج عادی حذف می‌شود.
- `application.log`: خروجی و خطاها در نسخهٔ frozen؛ اجرای سورس در ترمینال گزارش می‌دهد.

برای پشتیبان کامل، برنامه را ببندید و SQLite را به محل دیگری کپی کنید. برای انتقال یک مدرسه از JSON رابط استفاده کنید. SQLite یا session.url را در Git قرار ندهید. هنگام استفاده از مسیر سفارشی خارج از `data/`، آن مسیر را به ignore شخصی یا پروژه اضافه کنید.

برای بازیابی یک پایگاه دادهٔ پشتیبان، برنامه را ببندید، از فایل موجود نیز نسخه بگیرید، سپس فایل پشتیبان را در پوشهٔ دادهٔ موردنظر بگذارید و برنامه را دوباره اجرا کنید. نمونهٔ آزمایشی و دادهٔ کاری را با `--data-dir` جدا نگه دارید.

## آزمایش‌های خودکار

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check web/app.js
```

روی ویندوز، مسیر Python را با `.venv\Scripts\python.exe` جایگزین کنید. آزمایش‌ها از SQLite موقت استفاده می‌کنند و نباید پایگاه دادهٔ کاری را تغییر دهند.

پوشش فعلی شامل این موارد است:

- الزام ناسازگار در برابر ترجیح قابل نقض.
- تداخل ساعت واقعی، تجمیع، نیم‌زنگ و پوشش حضور.
- انواع قواعد، دبیر جایگزین و یکسان‌بودن دبیر.
- حفظ برنامهٔ قبلی و لغو حل هنگام خروج.
- revision، تاریخچهٔ محدود، بازیابی و رد نتیجهٔ snapshot قدیمی.
- نشست HTTP، Origin، ورود/خروج مدرسه و رد دادهٔ نامعتبر.
- PDF چهار نما، تعبیهٔ فونت و جلوگیری از PDF قدیمی.

تعداد فعلی ۲۳ تست است. تست‌های جدید را براساس رفتار و خطای قابل مشاهده اضافه کنید؛ صرفاً ساختار کد را تکرار نکنید.

### آزمایش واقعی مرورگر

Chrome و Node.js و Playwright لازم‌اند. برای نگه‌داشتن ابزار تست بیرون از سورس:

```bash
npm install --prefix /tmp/hamdars-browser playwright@1.58.0
.venv/bin/python run.py --data-dir /tmp/hamdars-browser-data --no-browser
```

در ترمینال دوم، داخل ریشهٔ پروژه:

```bash
mkdir -p test-results
NODE_PATH=/tmp/hamdars-browser/node_modules \
CHROME_PATH=/usr/bin/google-chrome \
node scripts/browser-test.cjs /tmp/hamdars-browser-data/session.url
```

`CHROME_PATH` را متناسب با محل Chrome تنظیم کنید. آزمون از Chrome نصب‌شده استفاده می‌کند و به دانلود مرورگر Playwright نیاز ندارد. دادهٔ آزمایشی باید جدا باشد: این اسکریپت واقعاً مدرسه، کلاس، درس، دبیر و قید می‌سازد و تغییر می‌دهد.

جریان مرورگر ایجاد و ویرایش، حل، چهار PDF، JSON، ورود دوباره، reload، موبایل، escape متن، stale شدن، ویرایش قید زمان جلسه و تغییر تقویم را بررسی می‌کند. تصاویر و خروجی‌ها داخل `test-results/` می‌روند و وارد Git نمی‌شوند. پس از تست، سرویس آزمایشی را ببندید.

## تغییر کد و افزودن قابلیت

برای قید تازه:

۱. نام نوع را به `KINDS` و قواعد اعتبارسنجی را به `domain.py` اضافه کنید.
۲. انتخاب دامنه و واحدهای زمانی را مشخص کنید.
۳. مدل قید را در `solver.py` بنویسید؛ حالت سخت و نرم باید از همان پرچم عمومی استفاده کنند.
۴. بررسی مستقل خروجی را در `audit.rule_ok` پیاده کنید.
۵. فیلدهای ورودی و تبدیل واحد را در فرم قید `web/app.js` اضافه کنید.
۶. نمونهٔ قابل حل، نمونهٔ ناسازگار و گزارش ترجیح را آزمایش کنید.
۷. راهنمای کاربر و جدول قرارداد قید را به‌روز کنید.

برای تغییر قالب سند، پیش از تغییر `schemaVersion` راه مهاجرت و رفتار واردکردن نسخهٔ قدیمی را مشخص کنید. نسخهٔ ناشناخته در حال حاضر رد می‌شود؛ migration عمومی خودکار نداریم.

برای تغییر PDF، علاوه بر signature فایل، نمونهٔ فارسی را تصویری بررسی کنید: اتصال حروف، ترتیب روز/زنگ، عنوان بلند، نیم‌زنگ و تجمیع. برچسب‌های کاربر نباید به markup فعال تبدیل شوند.

برای تغییر ذخیره‌سازی، حفظ تراکنش، کنترل revision، تاریخچه و رفتار شکست ضروری است. اطلاعات کاری کاربر را با دادهٔ تست جایگزین نکنید.

## ساخت ویندوز

این مرحله باید روی Windows 10/11 x64 اجرا شود؛ فایل اجرایی لینوکس را نمی‌توان به‌عنوان exe ویندوز توزیع کرد.

پیش‌نیازهای ماشین سازنده:

- Python 3.12 x64 و launcher دستور `py`.
- Inno Setup 6 در PATH یا مسیر استاندارد `Program Files (x86)\Inno Setup 6`؛ نسخهٔ جدید ۶ را استفاده کنید.
- اینترنت برای نصب وابستگی‌های Python و PyInstaller.

از ریشهٔ پروژه `build-windows.cmd` را اجرا کنید یا:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build-windows.ps1
```

اسکریپت محیط `.build-venv` می‌سازد، وابستگی‌ها و PyInstaller نسخهٔ مشخص را نصب می‌کند، تست‌ها را اجرا می‌کند، بستهٔ one-directory را می‌سازد و سپس Inno Setup را فراخوانی می‌کند. شکست هر مرحله ادامهٔ ساخت را متوقف می‌کند.

| خروجی | کاربرد |
| --- | --- |
| `dist/HamDars/` | نسخهٔ قابل‌حمل؛ **کل پوشه** باید منتقل شود، نه فقط exe |
| `dist/HamDars-Setup-1.0.0-x64.exe` | نصب‌کنندهٔ ویندوز |

اگر Inno Setup پیدا نشود، نسخهٔ قابل‌حمل ممکن است ساخته شده باشد اما نصب‌کننده ساخته نمی‌شود. Inno Setup را نصب و اسکریپت را دوباره اجرا کنید. خروجی بدون امضای تجاری است. کاربر نهایی به Python و Node احتیاج ندارد، اما مرورگر پیش‌فرض برای نمایش رابط لازم است.

دادهٔ کاربر خارج از مسیر نصب است. uninstall فایل داده را پاک نمی‌کند. هنگام انتشار نسخهٔ جدید، نسخه در `packaging/installer.iss`، پیام خروجی اسکریپت و نام بستهٔ سورس را هماهنگ کنید؛ AppId ثابت بماند تا هویت نصب عوض نشود.

### پذیرش یک نسخهٔ ویندوز

اسکریپت ساخت آماده است؛ اجرای واقعی نصب‌کنندهٔ ویندوز در محیط لینوکس آزمایش نشده است. پیش از انتشار فایل نصب:

1. روی Windows تمیز بدون Python، نصب و بازشدن رابط را بررسی کنید.
2. مدرسه بسازید، ببندید و دوباره باز کنید؛ اطلاعات باید باقی مانده باشند.
3. مدرسهٔ نمونه را وارد کنید، حل و PDF فارسی را امتحان کنید.
4. فایل JSON را روی حساب یا دستگاه دوم بازیابی کنید.
5. اجرای دوبارهٔ میان‌بر، تک‌نمونه‌بودن و خروج در زمان حل را بررسی کنید.
6. ارتقا و uninstall را امتحان کنید و حفظ داده‌ها را کنترل کنید.

## بستهٔ سورس

```bash
.venv/bin/python scripts/package-source.py
```

خروجی `dist/HamDars-source-1.0.0.zip` شامل کد، مستندات، فونت و نمونه است. محیط مجازی، Git، دادهٔ محلی در `data/`، فایل‌های build و نتایج تست کنار گذاشته می‌شوند. این ZIP نصب‌کننده نیست. دادهٔ حساس را در مسیرهای دلخواه داخل ریشه نگذارید؛ بسته‌بند برای نام‌های ناشناخته فیلتر محتوایی ندارد.

## رفع خطا

| نشانه | بررسی و اقدام |
| --- | --- |
| مرورگر باز نمی‌شود | default browser را بررسی کنید؛ در اجرای ترمینالی از session.url همان data-dir استفاده کنید. |
| خطای «از میان‌بر باز کنید» | آدرس پایه بدون cookie، نشست قبلی یا پورت اشتباه است؛ برنامه را از launcher باز کنید. |
| `ModuleNotFoundError` | با Python همان venv، `-m pip install -r requirements.txt` را اجرا کنید. |
| نصب قبلی نیمه‌کاره مانده | میان‌بر محیط موجود را دوباره نصب نمی‌کند؛ دستور نصب وابستگی‌ها را دستی اجرا کنید. |
| پورت اشغال است | مقدار `--port` را بردارید تا پورت خودکار انتخاب شود یا پورت آزاد بدهید. |
| پنجرهٔ دوم اطلاعات قدیمی دارد | آخرین نسخهٔ مدرسه را دوباره باز کنید؛ کنترل revision عمداً ذخیرهٔ قدیمی را رد می‌کند. |
| حل ناممکن است | سهمیهٔ کلاس، حضور، زمان ثابت، فیلتر دامنه و قیود مرتبط گزارش‌شده را بررسی کنید. |
| حل بدون نتیجه پایان یافته | زمان بیشتر بدهید؛ این وضعیت اثبات ناممکنی نیست. |
| PDF غیرفعال است | پس از آخرین ویرایش باید دوباره برنامهٔ معتبر ساخته شود. |
| بازیابی JSON رد می‌شود | نسخهٔ schema، ارجاع‌های حذف‌شده و برنامهٔ داخل فایل را بررسی کنید؛ فایل قدیمی موتورهای دیگر قابل ورود مستقیم نیست. |
| بعد از کپی سورس venv کار نمی‌کند | venv قابل انتقال عمومی نیست؛ در مسیر تازه آن را بازسازی کنید. |
| نسخهٔ اجرایی خطا می‌دهد | `application.log` در پوشهٔ داده را بررسی کنید؛ فایل نشست و دادهٔ مدرسه را بی‌دلیل همراه گزارش عمومی نفرستید. |

## محدودیت‌های فعلی

- یک کاربر محلی، یک حل هم‌زمان؛ همگام‌سازی ابری و همکاری هم‌زمان وجود ندارد.
- فقط قالب JSON خود برنامه بازیابی می‌شود؛ مهاجرت خودکار پرونده‌های قبلی مدارس پیاده نشده است.
- حداکثر ۱۵۰۰ رخداد و ۲۵۰هزار گزینهٔ اولیهٔ زمان/دبیر؛ زمان جست‌وجو حداکثر ۳۰۰ ثانیه است و زمان ساخت مدل جداست.
- تعداد زنگ روزها یکسان است؛ ساعت زنگ در سطح کلاس تنظیم می‌شود و روزبه‌روز متفاوت نیست.
- وزن‌دهی جمعی است، نه اولویت‌گذاری مرحله‌ای؛ جریمهٔ هر قید نرم یک‌باره است.
- خروجی PDF جدول‌های بزرگ می‌تواند چندصفحه‌ای باشد.
- تست ویندوز و امضای کد بخشی از کار انجام‌شدهٔ فعلی نیستند؛ این وضعیت باید در هر تحویل روشن بماند.
